02 // SPECIFICATION

执行规范详解

从思维到交付的完整链路，每个环节都有可核对的落点要求。

A

动手前：六步落点检查

判定任务类型与技术栈→扫描知识盲区→架构落点（模块与数据流）→方案落点（≥2条路径与取舍）→边界落点（空值/并发/网络/权限）→资源判定（CDN/图片/商用声明）。

六步全部完成，方可进入编码阶段。

B

实现中：最小改动 + 强制简化

只改必要处，不顺手重构。逐条过简化检查清单：DOM层删除空节点、CSS层合并重复值、JS层提取重复函数、依赖层剔除未使用模块。最终代码量应比初稿减少至少20%，或确认已达下限。

C

收尾前：零容忍交互自查

逐元素确认user-select: none；所有<img>满足4条防拖拽规则；点击元素无cursor:text。对照架构落点与边界清单反向验证。逐条过AI味禁止清单。确认任务完整交付，无半成品。

03 // DISCIPLINE

反模式与工程纪律

防止“过度工程”与“AI 味”的第一道闸门。只做被明确要求的事，拒绝幻觉式防御。

最小改动原则
只做被明确要求、或明显必要的改动。Bug 修复不要顺带重构周边代码；一个简单功能不要额外加可配置性。
拒绝过度抽象
不为一次性操作创建 helper/utility。三行相似代码，胜过一次过早的抽象。不为假设的“未来需求”做设计。
删除优于保留
未使用的东西彻底删掉。不留“将来可能用得上”的死代码。禁止向后兼容式 hack（如 `_unused` 占位）。
先读后改，不臆断
绝不提议修改你还没读过的代码。参数不确定就查清或询问，不填假值。遵循目标项目既有的代码风格。

04 // FORBIDDEN

AI 味禁止清单

以下绝对禁止，一旦踩中将被视为严重的工程失误。

色彩与渐变
禁止蓝紫渐变、粉蓝渐变、“科技感”默认渐变。禁止 Tailwind 默认 Indigo/Blue/Purple 品牌色滥用。
过度动效
禁止浮动上下动画、脉冲光环、过度 hover 放大（>1.05x）。禁止旋转 CSS 圆圈加载器。
资源与图标
禁止使用 Emoji 作为 UI 图标（必须用 SVG）。禁止 Undraw/Storyset 等 AI 插画占位。禁止假图片 URL。
模板化布局
禁止三栏等分卡片 + 大图标 + 标题 + 描述的功能特性区模板。禁止在工具/数据类界面硬塞无关图片。

06 // IMPLEMENTATION

指令实现方法

如何在实际工作流中让 AI 激活并严格遵循“铁律”的约束。

系统预设法 (System Prompt)
将完整的规范 Markdown 文件作为 AI 的“系统提示词”写入后台或自定义 AI 助手中。使约束成为默认认知。
上下文携带法 (Context Injection)
在每次开启新对话时，将规范文件作为附件上传或前置发送。适用于无法修改系统提示词的公共界面。
强制自检法 (Self-Reflection)
要求 AI 输出代码后，必须逐项对照“零容忍交互自查”清单并打勾，输出验证报告，否则视为未完成。
角色设定法 (Role Prompting)
明确要求 AI 扮演“享誉国际的全栈工程师与系统架构师”，拒绝“AI味”模板化输出，激活最高质量参数分布。

07 // DELIVERY

交付与协作规范

代码交付与工具使用过程中的工程准则（参考 Claude Code 实践）。

专用工具优先于 Shell
读写文件用专用工具（Read/Edit/Write），而非 cat/sed/awk。Shell 仅保留给真正的系统命令与终端操作。
独立并行，依赖串行
多个相互独立的操作，在一条消息里并行发起。若后一步依赖前一步的结果，必须串行，不得并行。
不生成或猜测 URL
除非确信该 URL 是为了帮助用户完成编程任务，否则绝不生成或猜测任何 URL。只使用用户提供的真实 URL。
多步任务用清单管理
面对多步骤任务，先列出可执行的步骤清单，逐项推进、逐项勾销。一步完成后立即推进下一步，不同时铺开。

模型能力对比 & 跨模型实测结论

DeepSeek-V4.1-Flash 架构：552B MoE（非对称）
激活参数：输入 8B / 输出 16B
上下文：1M Token

特点：原生多模态、强推理、Agent 优化
混元3（Hunyuan-3 / Hy3） 架构：295B MoE（快慢融合）
激活参数：21B（另 3.8B MTP）
上下文：256K Token
编程表现：SWE-Bench Verified 78.0
特点：Agent 强、成本低、前端/CI-CD 优势

1. 铁律对强模型效果显著：DeepSeek-V4.1-Flash 在深度思考模式下，有指令时 20s 完成核心功能，无指令则需 144s 且仍有布局缺陷。速度提升 7.2 倍，输出更干净、更可控。

2. 铁律对能力不足的模型效果有限：混元3（Hy3）虽然在 SWE-Bench 上表现不俗（78.0），但在本次“鹈鹕骑自行车”这类复杂创意前端任务中，深度模式下完全无法理解需求（纯色背景），快速模式下有指令仅渲染弹窗但交互失效。指令无法突破模型在特定任务上的能力边界。

3. 深度思考是必要条件：两个模型在关闭深度思考后，无论有无指令均输出崩溃。铁律是推理效率的放大器，但无法替代模型本身的推理深度。

4. 核心建议：铁律适用于 DeepSeek-V4.1-Flash、Claude、GPT-4 等强推理模型，用于压缩耗时、消除冗余、稳定输出。对能力不足或在此类任务上表现不佳的模型，优先更换模型，而非叠加指令。

适用场景

DeepSeek / Claude / GPT-4 等强推理模型的代码生成

需要快速原型验证的独立开发者与创意技术者
